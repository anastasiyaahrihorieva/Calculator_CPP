# C++ Projects Portfolio

> **This repo contains 2 projects.**

Данный репозиторий содержит два независимых проекта на языке C++, демонстрирующих различные подходы к проектированию архитектуры программного обеспечения, метапрограммированию и динамическому связыванию. Основной код каждого проекта и подробная документация изолированы в соответствующих ветках.

## Обзор проектов

### 1. Ветка `calculator`: Расширяемый консольный калькулятор
Проект представляет собой консольный калькулятор, вычисляющий математические выражения в инфиксной нотации. Парсинг выражений осуществляется с помощью алгоритма сортировочной станции (Shunting-yard) с переводом в обратную польскую запись (RPN). 

**Главная архитектурная особенность:** поддержка системы плагинов. Проект позволяет динамически подгружать новые математические функции из скомпилированных DLL-библиотек во время выполнения программы, полностью исключая необходимость перекомпиляции основного модуля.

### 2. Ветка `wrapper`: Универсальная обертка методов и движок команд (Command Engine)
Проект реализует систему динамической регистрации и вызова методов классов на основе паттерна "Команда". Инфраструктура позволяет инкапсулировать вызовы методов с произвольным числом аргументов (в рамках проекта тип аргументов упрощен до `int`) и вызывать их через строковые идентификаторы.

**Ключевые возможности `wrapper`:**
* **Умный маппинг аргументов:** Обертка принимает словарь (map) именованных параметров и значений в любом порядке. При вызове она автоматически сопоставляет ключи словаря с реальной сигнатурой переданного метода (например, извлекает `arg1` и `arg2` и передает их в правильном порядке).
* **Инкапсуляция (Decoupling):** Внедрен класс `Engine`, который выступает хранилищем команд. Это позволяет передавать указатель на `Engine` между различными модулями системы. Одни модули могут насыщать движок функционалом, а другие — вызывать эти методы (например, `"command1"`), передавая только словарь параметров.
* **Слабая связность:** Модули, вызывающие методы через `Engine`, не нуждаются в знаниях о конкретных классах-реализациях и не требуют подключения их заголовочных файлов (`#include`), что значительно упрощает архитектуру.
